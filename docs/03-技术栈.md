# 技术栈说明（dxf-editor）

> 一句话：**纯前端、零依赖、零构建步骤**的 JavaScript 单页应用——任何静态服务器（甚至直接双击）都能运行。

---

## 一、使用的语言 / 技术

| 类别 | 技术 | 说明 |
|---|---|---|
| 编程语言 | **JavaScript（ES5 兼容语法）** | 全部逻辑用 IIFE 包裹的经典 ES5 写法，兼容任何现代浏览器（Chrome/Edge/Firefox/Safari），无编译、无 TypeScript |
| 页面结构 | **HTML5** | `index.html` 单页：工具栏 / 画布 / 侧栏 / 状态栏 / 弹窗 |
| 样式 | **CSS3** | 深色 AutoCAD 风格 UI（暗色工具栏、青色高亮、状态栏配色） |
| 绘图 | **HTML5 Canvas 2D API** | 核心渲染：`canvas.getContext('2d')`，含 `Path2D`（批量路径）、`ctx.clip()`（XCLIP 硬裁）、`getImageData`（程序化验证） |
| 编码处理 | **TextDecoder**（内置） | GBK / Big5 / UTF-8 解码（`decode()` 嗅探策略），无第三方编码库 |
| SHX 字体 | **@mlightcad/shx-parser（MIT）** | 以 UMD 形式内置（`shx-parser.umd.js`），真实解析 AutoCAD SHX 矢量字形；`shx-parser.cjs` 供 Node 构建脚本用 |
| 二进制 DXF 解码 | **dxf-binary.js（零依赖）** | 检测 22 字节哨兵、按组码→数据类型映射解出值、转成等价 ASCII 字节流供解析器复用（保证与 ASCII 显示一致） |
| 运行时依赖 | **无**（零 npm 依赖、零 CDN） | 全部脚本本地文件；浏览器直接可用 |

## 四、关键设计决策

- **为什么零构建**：解析/渲染/字体全部是手写 JS，不需要打包器；SHX 解析器以 UMD 单文件内置，字体是静态 `.shx` 文件。改完刷新即生效，任何人（或 AI）都能直接上手改。
- **为什么 ES5**：避免任何转译步骤，确保 `file://` 与任意静态服务器都能直接跑；性能上 Canvas 是主要瓶颈，语言层面无差异。
- **为什么 Canvas 2D 而非 WebGL/库**：本项目目标是"与 AutoCAD 显示一致"的 2D 矢量图纸，Canvas 2D 足够且依赖最少；海量实体靠「按颜色+线型分组合并为单个 Path2D 一次描边」优化（见实现原理）。
- **为什么内置 SHX 而非 TTF**：AutoCAD 图纸的字体名（如 `hztxt.shx`、`gbcbig.shx`）对应 SHX 矢量字体，用系统 TTF 只能近似；内置 SHX 解析 + 标定表可做到与 AutoCAD `textbox` 真值 0 误差。
