# 实现原理（dxf-editor · 核心机制详解）

> 面向**开发者 / AI**：理解本项目的六个核心机制。读完应能独立定位和修改任意功能。

---

## 一、DXF 解析管线（`dxf-parser.js`）

```
原始字节/文本
  → decode()          编码嗅探：UTF-8 BOM → 严格 UTF-8 试解码（校验多字节合法性+中日韩计数）
                        → 失败则读 $DWGCODEPAGE（ANSI_936→GBK 等）→ 再失败 GBK 兜底
                        → 还原 \U+XXXX 转义
  → tokenize()        按行切组码对：{code, value}（组码=奇行，值=偶行）
  → splitSections()   SECTION/ENDSEC 划分（HEADER/TABLES/BLOCKS/ENTITIES/OBJECTS）
  → 逐节解析           TABLES：layers/linetypes/styles/views/vports
                        BLOCKS：block name + base point + entities[]
                        ENTITIES：按实体类型分发（line/lwpolyline/circle/arc/ellipse/
                          spline/insert/dimension/text/mtext/attrib/hatch/solid/...）
  → doc 对象
```

- **doc 关键字段**：`doc.header`（$ACADVER、$FILLMODE、$LTSCALE、$EXTMIN/$EXTMAX、$DWGCODEPAGE）、`doc.layers`、`doc.linetypes`、`doc.blocks`、`doc.entities`、`doc.layouts`、`doc.spatialFilters`。
- **组码语义**：62=颜色、420=真彩、8=图层、6=线型、48=线型比例、370=线宽、43=LWPOLYLINE 常量宽度、70=闭合标志（&1）、90=顶点数、10/20/30=坐标、210/220/230=OCS 法向量、330=owner 句柄、360=xdict 句柄。

## 二、块展开 `flatten()`（INSERT/DIMENSION 递归）

- **核心思想**：把块参照（INSERT）递归展开成**绝对世界坐标**的叶子实体，一次性完成属性继承，后续渲染零分支。
- **变换模型**：每个 INSERT 组成 2×3 仿射矩阵 `m`：
  ```
  local = T(ox,oy) · R(rot) · S(sx,sy) · T(-base)
  nm    = m_parent × local          // 嵌套块矩阵连乘
  ```
  阵列（cols×rows）在插入旋转坐标系中按 `colSpace/rowSpace` 偏移展开。
- **镜像**：`det = a·d − b·c < 0` 表示镜像。镜像后：凸度 `bulge` 取反；ARC 端点方向用 `atan2(m.b·cosθ+m.d·sinθ, m.a·cosθ+m.c·sinθ)` 精确变换并交换起止角（旧公式只对 y 轴镜像正确）。
- **OCS→WCS**：实体带法向量（extX/extY/extZ≠(0,0,1)）时先转回世界再乘矩阵，解决倾斜椭圆/文字错位。
- **属性继承**（就地完成 AutoCAD 规则）：
  - 块内层 `"0"` → 继承 INSERT 有效层（`ctx.layer`）；
  - BYBLOCK 颜色（color=0）→ 解析成 INSERT 的 `trueColor`/ACI；
  - BYBLOCK 线型 → 继承；
  - 祖先层冻结 → 记录 `_anc` 供渲染期隐藏。
- **XCLIP（AcDbSpatialFilter）**：INSERT 的扩展字典链里找 `AcDbSpatialFilter`，取其 group-40 前 12 值组成 `FILTER_M`（filter-ECS→块系）；裁剪矩形经 `FILTER_M` → `INSERT_M` 映射到世界系，与父裁剪求交后附加到叶节点 `_clip`。这是「网页 28 张图 vs CAD 3 张图」问题的根因修复。
- **输出**：每个叶子实体带 `_bb`（世界包围盒）、`_clip`（裁剪区）、`_blk`（来源块名）、`_anc`（冻结祖先链）。

## 三、渲染管线（`dxf-render.js`）

### 空间与视图
- 每个空间（模型/布局）一个实体列表；`render()` 先 `_prepare()` 算包围盒与保存视图判定，再按可见窗口剔除（`_bb` 粗判）。
- **保存视图判定**：统计真正落入视口窗口内的实体并集包围盒占比 `fill∈[0.10,8.0]` + 实体占比 `n≥20 且 ≥1%`，否则回退 ZOOM EXTENTS（防空白/防批注误接受）。

### 三遍绘制 `_drawEntityList`
1. **填充遍**：HATCH（`_drawHatch`）、SOLID/TRACE/3DFACE、**闭合宽多段线**（`_fillPoly`，见机制五）。
2. **线遍**：非填充实体按 `颜色|线型` 键分组成 `Path2D`，每组合并一次 `ctx.stroke()`（海量实体性能关键）；线宽 1px 固定，坐标经 `round()+0.5` 像素中心吸附。
3. **文字遍**：TEXT/MTEXT/ATTRIB 最后统一绘制（文字置顶，避免被后绘制的裁剪组几何覆盖）。

### XCLIP 硬裁
- 按 `_clip` 对实体分组，同一裁剪矩形共享一次 `ctx.clip()` → 长构造线在边界被硬裁，不跨出图框。

### 图纸空间（布局）
- LAYOUT 对应 `*Paper_Space` 块建 `isPaper=true` 空间；`_extractViewports()` 抽取 VPORT（视口中心/模型视图中心/宽高/扭转）；渲染时白纸底 + 逐视口裁剪 + 视口内按模型范围 ZOOM 适配 + 图纸空间实体（标题栏/边框/注释）。

## 四、HATCH 图案填充

- **边界环**：`boundaryLoops`（含 line/arc/ellipse/spline 边与 polyline 环）求值成 `Path2D`。
- **图案线**：`patLines`（图案定义线：角度/基线偏移/虚线）在包围盒内按缩放铺线，**线宽随缩放自适应**（防缩略图糊块）。
- **兜底**：无图案定义（非标准/自定义图案）→ `_hatchFallback` 画 45° 近似线（保证可见，非精确）。
- **SOLID 填充**：pattern=SOLID 直接 fill。

## 五、闭合宽多段线实心填充（AutoCAD FILLMODE 对齐）

- **为什么**：AutoCAD `$FILLMODE=1` 时，闭合且带宽度的 LWPOLYLINE/POLYLINE 会把内部填充成实体色（电气设备块的"亮绿色实心"外框就是这种画法）。
- **判定 `_isWideClosedPoly(e)`**：①闭合：`f70&1`、首尾顶点重合、或首点在后续顶点重现形成回路（本例 `f70=0` 但几何闭合）；②宽度>0：`constWidth`（组码43）或各顶点 `startWidth/endWidth`。
- **填充门槛 `_isFillablePoly(e)`**：避免把"图框/标题框"（PUB_TITLE 巨框）也填满——要求 **世界包围盒短边 / 整图短边 < 1%**。
  - 为什么用世界短边：`constWidth` 是实体局部值、**不会被块变换缩放**（`xformEntity` 只变换顶点/半径，不变 constWidth），局部/世界混比会量纲错乱；纯世界坐标比较最稳。
  - 设备块短边≈60、整图短边≈627575 → 0.01% < 1% → 填充 ✓；PUB_TITLE 短边 28700 → 4.6% > 1% → 空心描边 ✓。
- **整图包围盒 `_getDocBounds()`**：惰性遍历所有空间实体 `_bb` 并集并缓存。
- **绘制 `_fillPoly`**：`_pathPoly` 建 Path2D，f70=0 但几何闭合时补 `lineTo(起点)`，`ctx.fill(P,'evenodd')`，颜色 `colorOf(e)`（实体→图层继承链）。

## 六、1px 发丝线像素中心吸附（反走样）

- canvas 2D 中 1px 描边居中在整数设备像素时跨两像素各 50% → 50% 灰（闪烁/消失）。
- 修复：描边前把 `SX/SY` 重定义为 `x => Math.round(_sx(x)) + 0.5`，使 1px 线精确覆盖一整像素。仅影响描边坐标，不影响填充/文字/裁剪框。

## 七、文字渲染与 SHX 字体

- **字高解析**：DXF 中 TEXT/MTEXT 的 group 40 为 `0` 时语义是「使用样式固定高度」；样式高度也为 `0` 时回退到 `$TEXTSIZE`。渲染器统一走 `_resolveTextHeight(e)`：`r40>0 ? r40 : STYLE.height : $TEXTSIZE : 2.5`，避免把 `0` 误判为未设置而硬编码成 `2.5` 图形单位（毫米图里几乎看不见）。
- **块内文字字高随插入比例缩放**：`flatten()` 的 `xformEntity(e, m, doc)` 在展开 INSERT 时，先解析本地字高，再乘插入矩阵平均缩放 `sc`，使块内文字与世界几何保持正确比例。
- **系统字体近似（当前默认）**：`SHX_SUBST` + `_fontFamilyFor` 按字体名映射系统字体；`file://` 下 SHX 无法加载也走此路。
- **真实 SHX 矢量字形（`shx-fonts.js`，已具备待切换）**：
  - `@mlightcad/shx-parser` 解析 SHX 字形为矢量折线；
  - 字形→世界坐标：`worldX = H·s·(emX+lx)`、`worldY = H·(s·ly+oy)`，`s/oy` 逐字体标定（`shx-calib.json`，AutoCAD `textbox` 1068 真值点拟合，33/34 字体 0 误差）；
  - CJK 多字节：GBK/Big5 反向查表（`TextDecoder` 遍历双字节）定位 bigfont 字形码；
  - `acad-fmp.json`（521 条）复刻 AutoCAD 字体映射，让选字与 CAD 一致。

## 八、编码识别（UTF-8 / GBK）

- 策略：`UTF-8 BOM` → `严格 UTF-8 试解码`（自写校验器，不依赖 TextDecoder，同时统计中日韩字符数判断置信）→ 失败读 `$DWGCODEPAGE`（ANSI_936→gbk、ANSI_950→big5、UTF8→utf-8 等）→ 再失败 GBK 兜底 → `\U+XXXX` 转义还原。工程文件常有混杂/半截编码，该策略实测全通过。

## 九、文字框选（含嵌套块内文字）

- `flatten()` 已把嵌套块内文字变换到世界坐标 → 框选天然命中块内文字，零额外处理。
- `finalizeTextPick`：屏幕框→世界框→过滤 `activeEntities()` 中 `TEXT/MTEXT/ATTRIB` 且包围盒相交者→`readingOrderRows` 按行阅读顺序排序→弹窗逐条/全部复制/导出 .txt，收框自动复制（对齐广联达快速看图）。

## 十、保存（扁平化写回）

- `DxfWriter.writeFlat(doc, activeEntities)`：把当前空间展开后的实体写回 ASCII DXF（含新增/移动/删除）；`minimalTables()` 对精简文档安全兜底。已知取舍：块结构被扁平化、外部参照/其它布局不在导出范围。

## 十一、二进制 DXF 预处理（dxf-binary.js）

- **目标**：让 AutoCAD「Binary DXF」文件与 ASCII DXF **显示逐像素一致**——不另写渲染分支，而是把二进制字节流翻译成「等价 ASCII DXF 字节流」，再喂给既有管线。
- **哨兵检测**：文件头 22 字节 = `AutoCAD Binary DXF\r\n` + `0x1A` + `0x00`；命中才进入二进制路径，否则原样当文本处理（ASCII DXF 不受影响）。
- **组码→值解码**：主流是 **大端（big-endian）** 的「2 字节组码 + 值」：
  - 字符串类（0–9 / 100 / 102 / 105 / 300–309 / 320–369 / 390–399 / 410–419 / 430–439 / 470–479 / 480–481 / 999 / 1000–1009）：2 字节长度（含结尾 `\0`）+ 字符字节；读取时去掉结尾 `\0`。
  - 双精度类（10–39 / 40–59 / 110–149 / 210–239 / 460–469 / 1010–1059）：8 字节 IEEE754 大端（`DataView.getFloat64`，老环境手动重组兜底）。
  - 短整（60–79 / 170–179 / 270–289 / 400–409 / 1060–1070）：2 字节；长整（90–99 / 160–169 / 420–459 / 1071）：4 字节。
  - 布尔（290–299）：1 字节（0/1）；字节（370–389）：1 字节。
  - 二进制块（310–319）：2 字节长度 + 原始字节，输出为十六进制文本（ASCII DXF 中 310 即存十六进制串）。
- **输出字节流**：每对输出 `组码文本\r\n值文本\r\n`。关键：**字符串字段保留原始字节**（UTF-8 或 GBK）直接写回，这样下游 `decode()` 的 UTF-8/GBK 嗅探与打开同编码 ASCII 文件走同一分支；数值按真实值文本化（double 用最短往返表示，保证精度无损）。
- **一致性保证**：经 `binaryToText()` 后，二进制 DXF 变成「一份用原编码写出的 ASCII DXF 文件」，后续 `parse → flatten → render` 与真·ASCII 文件 100% 同源，故渲染必然一致。
- **兼容性**：浏览器经 `FileReader.readAsArrayBuffer` 读入、Node 经 `fs` 读入均支持；`index.html` 在 `dxf-parser.js` 前加载 `dxf-binary.js`（挂 `global.DxfBinary`）；Node 侧 `require('./dxf-binary')` 带 try/catch，未加载也不影响 ASCII 解析。
